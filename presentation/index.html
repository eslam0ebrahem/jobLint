Part 1

Why?

The problem I set out to solve.

The Problem

Job hunting is a
data-entry job

📋

Copy-paste pipeline

Title, company, description — re-typed by hand from job boards into spreadsheets and notes apps.

🧩

No overview

After 50+ applications: scattered spreadsheets, forgotten stages, zero status tracking.

🎲

Gut-feel decisions

"Should I apply to this job?" — answered by instinct, not by data. Time gets wasted on bad fits.

The Problem · Deeper

Two hidden problems
behind the mess

🧠

Fit evaluation is expensive

Long descriptions × your actual stack = real analysis time. Too slow — so we apply blind.

⚠️

Red flags hide in plain sight

Commission-only pay. Unpaid "experience". A junior role demanding 5+ years. Easy to miss at scroll speed.

I wanted a tool that reads the posting for me, scores it against my profile, and keeps the pipeline tidy.

Part 3

How?

Architecture & the tech stack.

How · Architecture

One gateway, layered use cases, explicit adapters

🌐 LinkedIn / Indeed
Job sites — dynamic, redesigned often
⇄
🖥️ React entrypoints
Typed gateway clients + focused state hooks
⇄
⚙️ Background composition
Dependency wiring · dispatch · events · lifecycle
↓
🧩 Application services
Job · backup · settings · AI review workflows
⇄
📐 Pure domain
Identity · facts · evaluator · packets · calibration · backup
⇄
🔌 Infrastructure adapters
IndexedDB v8 · storage.local · alarms · detectors · AI HTTP

Dependencies point inward: pure policies at the core, replaceable adapters at the edge, and AI remains a plug-in.

How · The Stack

Modern stack, zero backend

⚡ WXT 0.21
Extension bundler: hot reload, auto-manifest, Firefox builds
⚛️ React 19
Four React surfaces over the gateway; no state library
🛡️ TypeScript 5.9
Typed gateway; compile, lint, and 55 tests across 15 suites
🎨 Tailwind v4
CSS-first config via Vite plugin, shared styles
🗄️ idb + IndexedDB
Promise wrapper; v8 jobs/events/discovery/follow-up stores with identity deduplication
🔌 OpenAI-compatible API
OpenRouter · OpenAI · Groq · MiniMax · Ollama — direct, own key

Chrome Manifest V3 / Firefox MV2 · permissions: activeTab, storage, tabs, scripting · zero remote calls besides your AI provider.

Part 4 · Insights

Lessons learned

1
The DOM is the hard partJob sites redesign constantly — detection must be layered (selector fallbacks, URLs, meta tags) and defensive by default.
2
Shadow DOM is non-negotiableWhen you inject UI into pages you don't control, style isolation is the difference between "works" and "works everywhere".
3
Local-first is a featureNo accounts, no servers, no privacy tradeoffs — users can feel the difference.
